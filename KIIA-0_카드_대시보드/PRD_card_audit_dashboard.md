# 법인카드 이상거래 탐지 대시보드 PRD

> 본 자료는 실습용 가상 데이터이며 실재 인물·기관·거래와 무관하다.

제품 요구사항 문서(Product Requirements Document)다. 이 문서를 AI 도구에 그대로 전달하면 명세에 따라 단일 HTML 대시보드 아티팩트를 생성하도록 설계되었다. 아래 규칙과 임계값, 가중치는 실습용 예시이며 특정 기관의 공식 기준이 아니다. 생성된 대시보드의 계산과 분류 결과는 감사 결론이 아니라 후속 확인의 출발점으로만 사용한다.

---

## 1. 목적

법인카드 사용내역 전건에 사전 정의한 탐지 규칙을 일괄 적용하여, 추가 확인이 필요한 거래를 위험점수 순으로 제시하는 단일 페이지 대시보드를 만든다. 감사인이 임계값을 조정하면 결과가 즉시 다시 계산되어, 조직의 기준에 맞는 이상 판정 구간을 직접 시험할 수 있다. 서버나 별도 설치 없이 브라우저 안에서 작동하는 단일 HTML 파일(아티팩트)로 구현한다.

이 도구가 대신하는 것은 판단이 아니라 계산이다. 감사인의 경험적 기준을 규칙과 가중치로 옮겨 444건 전체에 한 번에 적용하며, 부적정 사용 여부의 확정은 감사인이 증빙과 규정을 대조해 수행한다.

## 2. 대상 데이터

- 파일: `corporate_card_transactions.xlsx`
- 시트: 「카드사용내역」
- 건수: 444행
- 기간: 2026년 3월
- 카드번호: `****-****-****-3045` 형태로 뒤 네 자리만 남기고 마스킹
- 사용자: 김○○ 형태로 비식별 처리
- 열 구성: 11열(6절 데이터 스키마 참조)

## 3. 탐지 규칙

각 거래에 아래 일곱 규칙을 적용하고, 걸린 규칙의 가중치를 합산해 위험점수를 산출한다. 한 거래가 여러 규칙에 동시에 걸리면 가중치가 누적된다.

| 규칙 | 규칙명 | 판정 로직 | 기본 임계값 | 가중치 |
|------|--------|-----------|-------------|--------|
| R1 | 심야·새벽 사용 | 사용 시각이 심야·새벽 시간대에 해당 | 22:00~06:00 | 30 |
| R2 | 주말 사용 | 토요일 또는 일요일 거래 | 활성 | 15 |
| R3 | 부적절 업종 | 업종이 유흥·골프·면세·백화점에 해당 | 유흥/골프/면세/백화점 | 35 |
| R4 | 분할결제 의심 | 동일 사용자·가맹점의 단시간 반복 결제 | 30분 내 3건 이상 | 40 |
| R5 | 중복청구 의심 | 동일 사용자·가맹점·금액의 짧은 간격 반복 | 동일 금액 10분 내 | 35 |
| R6 | 고액 거래 | 1회 사용액이 임계 금액 초과 | 500,000원 초과 | 20 |
| R7 | 한도 임박 | 단일 거래가 설정 한도 비율에 근접 | 한도의 95% 이상 | 25 |

R3의 부적절 업종은 상호명이 아니라 업종 값을 기준으로 판정한다. R1의 시작·종료 시각, R6의 금액, R7의 한도 비율은 대시보드에서 감사인이 조정할 수 있어야 한다.

## 4. 위험점수 구간

합산 위험점수를 세 구간으로 분류한다.

| 구간 | 위험점수 | 판정 |
|------|----------|------|
| 정상 | 0~30 | 추가 확인 불요 |
| 주의 | 31~60 | 증빙·목적 확인 대상 |
| 고위험 | 61 이상 | 우선 확인 대상 |

구간 경계는 실습용 기준이며, 등급은 검증 전까지 감사 결론에 사용하지 않는다.

## 5. UI 구성

대시보드는 위에서 아래로 세 영역으로 구성한다.

1. 요약 카드: 총 거래 건수, 총 사용금액 합계, 규칙별 탐지 건수, 구간별(정상·주의·고위험) 건수를 카드 형태로 상단에 배치한다.
2. 임계값 슬라이더: R1 심야 시작·종료 시각, R6 고액 기준 금액, R7 한도 비율, 위험점수 구간 경계를 조정하는 슬라이더를 둔다. 슬라이더를 움직이면 표와 요약 카드가 즉시 다시 계산되어야 한다.
3. 결과 테이블: 위험점수 내림차순으로 거래를 정렬한다. 각 행에는 거래 정보와 함께 걸린 규칙을 R3, R6과 같은 태그로 표시하고, 위험점수와 구간을 함께 보여 준다.

## 6. 데이터 스키마

대시보드는 아래 11개 열을 그대로 읽어 처리한다. 열 이름이 어긋나면 매핑 오류가 발생하므로, 엑셀의 머리글과 아래 스키마를 일치시킨다.

| 열 이름 | 자료형 | 설명 |
|---------|--------|------|
| 거래ID | 문자열 | 거래 고유 식별자(T00001 형태) |
| 사용일시 | 일시 | `2026-03-DD HH:MM` 형식. R1·R2·R4·R5 판정에 사용 |
| 사용자 | 문자열 | 비식별 처리(김○○ 형태) |
| 부서 | 문자열 | 사용자 소속 부서 |
| 카드번호 | 문자열 | 뒤 네 자리만 남긴 마스킹 값 |
| 가맹점명 | 문자열 | 가맹점 상호. 업종 판정의 보조 정보 |
| 업종 | 문자열 | 음식점·유통·주유·유흥·골프·면세·백화점 등. R3 판정 기준 |
| 금액 | 정수 | 원 단위 사용금액. R6·R7 판정에 사용 |
| 승인상태 | 문자열 | 정상·취소 등 |
| 사용목적 | 문자열 | 업무·접대 등 |
| 비고 | 문자열 | 참고 메모 |

날짜는 문자열이 아니라 일시로 해석하고, 금액은 숫자로 처리한다. 카드번호와 거래ID는 문자열로 다루어 앞자리 손실을 막는다. 결측 시각이나 금액이 있는 행은 오류로 중단하지 말고 해당 규칙만 건너뛴 뒤 별도로 표시한다.

## 7. 범위 제외

- 카드번호 복원, 사용자 실명 식별 등 비식별 데이터의 재식별은 수행하지 않는다.
- 개별 거래의 부정 여부를 확정하지 않는다. 규칙은 추가 확인 대상을 선별할 뿐이다.
- 외부 시스템 연동, 실시간 거래 수집, 사용자 인증은 이 실습의 범위가 아니다.
- 원자료 파일을 대시보드에 불필요하게 노출하지 않으며, 내장 데이터는 실습용 가상 데이터로 한정한다.

## 8. 산출물

- 444건 전체에 R1~R7 규칙이 적용되고, 임계값 변경 결과가 즉시 반영되는 단일 HTML 대시보드 한 페이지.
- 요약 카드, 임계값 슬라이더, 위험점수 내림차순 결과 테이블을 포함한다.
- 검증 항목: 총 거래 건수와 금액 합계가 원자료와 일치하는가, 일곱 규칙이 명세대로 계산되는가, 경계값과 결측치를 올바르게 처리하는가, 원자료가 파일에 불필요하게 노출되지 않는가.
