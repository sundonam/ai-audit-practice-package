# 감사 업무 폴더 지침

## 1. 기본 원칙

- 모든 작업은 감사 조서, 위험 평가표, 개선 권고안 작성에 활용한다
- 모든 판단은 제공된 파일과 명시된 기준에 근거한다
- 근거가 부족한 내용은 "확인 필요"로 표시한다
- AI가 제시한 결과를 감사결론으로 자동 확정하지 않는다. 최종 판단과 승인은 감사인이 한다

---

## 2. 문체 기준

- 간결하고 직접적으로 작성한다
- 감정적 표현, 과도한 추정 사용을 금지한다
- 문장 서술 순서: 사실 → 기준 → 차이 → 영향 → 권고

---

## 3. 감사 조서 양식

### 기본 구조
1. 감사 대상 및 범위
2. 관련 법령·내부 규정
3. 확인된 사실
4. 적용 기준과의 차이
5. 위험 등급 판정
6. 조치 권고 사항

### 작성 규칙
- 사실과 의견을 명확히 구분한다
- 수치, 날짜, 근거 문서명을 반드시 명시한다
- 추측성 표현("~인 것 같다", "아마도") 사용 금지
- 문단 당 하나의 핵심 사실만 기술한다

---

## 4. 위험 등급 기준

| 등급 | 기준 | 처리 방향 |
|------|------|-----------|
| 위험 (High) | 법령·규정 위반, 재정 손실 발생 또는 우려 | 즉시 시정 요구 |
| 주의 (Medium) | 내부 절차 미준수, 통제 미흡 | 개선 권고 |
| 양호 (Low) | 경미한 절차상 미비 또는 참고 사항 | 관찰 기록 |

- 등급 판단 근거는 반드시 해당 법령 조항 또는 내부 규정 조항을 병기한다
- 등급 결정이 어려운 경우 "확인 필요"로 표시하고 추가 검토 사항을 기술한다

---

## 5. 보안 및 민감 정보 처리

- 개인정보, 주민등록번호, 계좌번호, API 키 등은 결과물에 포함하지 않는다
- 필요한 파일만 제공받아 처리한다
- 민감 정보는 사전 제거 또는 마스킹 후 작업한다
- 결과물 공유 전 민감 정보 포함 여부를 반드시 검토한다

---

## 6. 산출물 파일명 규칙

모든 산출물 파일명은 영어로 작성하여 일관성을 유지한다.

```
Audit_Workpaper_[Topic]_[YYYYMMDD].docx
Audit_Risk_Assessment_[Period].xlsx
Audit_Improvement_Recommendations_[Topic].docx
Audit_Interview_Record_[Subject]_[YYYYMMDD].docx
Audit_Final_Report_[Institution]_[Period].docx
```

---

## 7. 출력 형식

- 감사 조서: DOCX (표준 양식 준수)
- 위험 평가표: XLSX (위험 등급 색상 구분 포함)
- 개선 권고안: DOCX (처분 요구 형식)
- 요약 보고: PDF (최종 제출본)

---

## 8. 작업 품질 검증 기준 (루브릭)

작업 결과물 생성 후 아래 기준을 충족하는지 자체 검증한다.

- [ ] 사실과 의견이 명확히 구분되어 있는가
- [ ] 모든 수치·날짜·근거 문서가 명시되어 있는가
- [ ] 위험 등급 판단 근거가 법령·규정 조항과 연결되어 있는가
- [ ] 감정적 표현이나 추측성 서술이 없는가
- [ ] 민감 정보가 결과물에 포함되지 않았는가
- [ ] 파일명이 영어 규칙을 준수하고 있는가

기준 미달 항목이 있는 경우 해당 부분을 수정하거나 처음부터 재작성한다.
